# KubeShield AI — Cyber Arena 2026 · PS-09

**Kubernetes Security Misconfiguration Detection Platform** — a Streamlit prototype for defensive, pre-deployment review of Kubernetes YAML manifests.

## What is included
- Streamlit dashboard with YAML upload and vulnerable/hardened demo scenarios.
- Multi-document YAML parsing with PyYAML.
- 14 deterministic checks covering selected container, pod, RBAC and manifest-bundle risks.
- Severity-ranked findings with evidence and remediation guidance.
- JSON security report export.
- Sample vulnerable and hardened manifests.
- Pitch deck, demo script, architecture notes and regression tests.

## Run on Windows 11
1. Extract the ZIP.
2. Open the extracted `KubeShield_AI_Hackathon` folder.
3. Click File Explorer's address bar, type `cmd`, press Enter.
4. Run one command at a time:

```bat
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements.txt
py -m streamlit run app.py
```

The local app opens at `http://localhost:8501`.

## Publish the public live demo (about 5–10 minutes)
A `localhost` address is not public. Deploy the GitHub repository using Streamlit Community Cloud:

1. Create a GitHub repository at https://github.com/new (name: `KubeShield-AI`).
2. Upload the **contents** of this project folder to the repository root. Ensure `app.py`, `requirements.txt`, `samples/`, and `.streamlit/config.toml` are at the root.
3. Open https://share.streamlit.io/ and sign in with GitHub.
4. Select **Create app** → choose repository `KubeShield-AI` → branch `main` → main file `app.py` → **Deploy**.
5. Wait for Streamlit to build the app. Copy the generated `https://....streamlit.app` URL.
6. Test that URL in a private/incognito browser window and on a phone before submitting it.

The public URL is generated by Streamlit after deployment. It cannot be created or truthfully supplied in advance from this chat.

## Hackathon demo flow (90 seconds)
1. Open **Security Scanner** and choose **Vulnerable deployment**.
2. Show the score, CRITICAL/HIGH counts and expand one finding to explain evidence and remediation.
3. Switch to **Hardened deployment** and show the safer configuration.
4. Open **Detection Rules** and explain that checks are deterministic rules.
5. Download the JSON report.
6. State the prototype's scope and limitations honestly.

## Scope and limitations (say this clearly)
- Static analysis of uploaded YAML only; no live cluster connection, `kubectl` actions or resource modification.
- Rule-based prototype; despite the product name, this build does not use an AI/ML model.
- The 14 checks are selective, not a complete CIS Kubernetes Benchmark or full cluster audit.
- NetworkPolicy check verifies presence in the uploaded YAML bundle; it does not validate policy semantics or cluster-wide coverage.
- Security score is a simple heuristic, not a certified risk score.
- Human validation is required before applying remediation.
